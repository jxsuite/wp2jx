# Bindings: what the Jx static build evaluates

This is the authority for every `${...}` that wp2jx emits. Everything here was measured by building real tiny Jx projects (`@jxsuite/compiler` 4.0.2, `@jxsuite/site` 2.0.2, `@jxsuite/parser` 1.8.2, `jx build` plus `jx validate`), and `tests/dynamic-build.test.ts` asserts each rule again on every run, so a Jx upgrade that changes one goes red there. Case ids in square brackets (`[T1]`) are the test names.

The probe project is a collection `items` (Markdown, `@jxsuite/parser`) with a route `pages/c/[slug].json` that holds a `ContentEntry`:

```json
{
  "$paths": { "contentType": "items", "param": "slug", "field": "slug" },
  "title": "${state.entry.data.title}",
  "state": {
    "entry": {
      "$prototype": "ContentEntry", "contentType": "items", "field": "slug",
      "id": { "$ref": "#/$params/slug" }, "$src": "@jxsuite/parser/ContentEntry.class.json",
      "timing": "compiler"
    }
  },
  "children": [ ... ]
}
```

"The build" below means the static site build. A binding the build cannot evaluate is not an error: it is left for the browser (`data-bind :text-content="_t0"`, and the page ships `app.js`). That is the failure mode to avoid, because the element is then empty in the HTML.

## 0. The rules on one page

1. **One timing.** Put `"timing": "compiler"` on the `ContentEntry` (and on every `ContentCollection`) of an entry template. Then a page whose bindings all resolve ships **no JavaScript** `[TIM1]`. Without it the page is "dynamic" (`isDynamic` sees a `$prototype`), its HTML is complete but it also ships `app.js` and a client runtime `[TIM2]`.
2. **A single `${expr}` that evaluates to `undefined` or `null` is not resolved.** The build keeps `data-bind` for the client and the element comes out empty `[A4]`. Always coalesce: `${state.entry.data.x ?? ''}` for text, `${state.entry.data.x || false}` where the attribute should disappear when there is nothing `[A2]`. A template with a literal part (`a ${x} b`) never has this problem; it prints `undefined` instead `[T8]`, so coalesce there too.
3. **`false` is the only value that means "omit this attribute"** (`href`, `src`, `target`, `rel`, `hidden`, `disabled`, ...). `true` writes a bare presence attribute (`hidden`, `disabled`) and the word for `aria-*`, `draggable`, `contenteditable`, `spellcheck`. `''` writes `attr=""` `[A2]`.
4. **Bindings live in `textContent`, `innerHTML`, `attributes.*` and flat `style` values.** They are evaluated there `[T1] [A1] [H1] [S1]`. Everywhere else they are not, or are evaluated twice, or are lost (rule 5).
5. **Never bind these** (each measured): `className` and `id` (silently dropped under `timing: "compiler"`, and an element with its own `style` whose first class or `id` is a binding gets the raw `${...}` as its CSS selector `[C1] [C2]`); the top-level `hidden`, `title`, `tabIndex`, `lang`, `dir` (emitted, but also bound on the client, so the page ships JS `[X1]`; use `attributes.hidden` and so on); a text child in `children` (`"a ${x} b"` is printed literally `[K1]`); anything inside a nested style block (`":hover"`, `"& a"`, `"::before"`, `"@--md"`: the declaration or the whole rule is silently dropped `[S4]`); `$switch` (client rendered, empty in the HTML `[Q5]`); `Array.items` as a template string (client rendered `[Q4]`).
6. **A text child that holds a binding goes in an element's `textContent`.** Mixed inline content with bindings becomes `innerHTML` or, when it must stay structured, the text is wrapped in a `<span>` (`finishNodes` does this) `[K1]`.
7. **`textContent` and attributes are HTML-escaped by the emitter; `innerHTML` is raw.** A bound plain-text value in `innerHTML` must be escaped by the expression `[T7] [H3]`; wysiwyg HTML goes in `innerHTML` as is `[H1]`.
8. **A string that contains a binding is a JavaScript template literal.** Its literal parts need `\` written `\\` and a backtick written `` \` ``; a string with no binding is never evaluated and is verbatim `[E1]`. A literal `${` has no spelling that survives in `textContent` or an attribute (`&#36;{` shows as the text `&#36;{` there); in `innerHTML` it is `&#36;{` `[E2]`.
9. **Conditional rendering is `attributes.hidden` plus a rule.** `hidden` is evaluated at build; a class rule `display:flex` beats the browser's `[hidden]`, so the element's style also carries `"&[hidden]": {"display": "none !important"}` (a static nested rule, which works) `[Q1]`. `$switch` and `Array` with a template `items` render on the client, not at build; `children: ["${cond ? [ {...node} ] : []}"]` omits the element at build but the subtree is a JavaScript literal in a string `[Q3]`.
10. **Loops over entry data use a JSON pointer, not a template:** `{"$prototype":"Array","items":{"$ref":"#/state/entry/data/rows"},"map":{...}}`, with `${$map.item.x}` and `${$map.index}` inside `[L1]`. An empty or missing array turns the whole parent into a client render (its static siblings are lost from the HTML) `[L3]`, so build lists that can be empty as an `innerHTML` expression `[H4]`.
11. **Dates are strings** (`2024-02-15T17:30:00Z`, `date-time` is normalised to UTC), formatted in an expression with `new Date(x).toLocaleDateString('en-US', {..., timeZone})` and `Intl.DateTimeFormat` `[D1]`.
12. **A component instance takes bindings in `$props`**, arrays and objects included; a `$props` binding that evaluates to `undefined` arrives as `null` and prints `null` `[M2]`. The component's own `${state.x}` bindings follow the same rules as a page's `[M1]`.
13. **Braces in an expression must balance outside its strings too.** The build finds the end of a `${...}` by counting `{` and `}` without reading string literals, so `${x ? '{' : false}` is not one expression to it: the attribute loses its type and prints `disabled="false"` `[A5]`. wp2jx writes every string literal of a binding through `jsString`, which spells `{`, `}`, `$`, a backtick and the line separators as `\uXXXX` escapes.
14. **A plain page evaluates `${...}` at build too, with no state at all** `[D2]`: `new Date()` in a `textContent` is the date of the build, and the page ships no JavaScript. `{currentdate}`, `<ccd>custom_current_date</ccd>` and their kin are written that way, not frozen at conversion time.

## 1. Where a binding is evaluated

"Static" means resolved into the HTML by `jx build` with `timing: "compiler"` on the entry. "Client" means `data-bind` plus `app.js`. "Lost" means silently absent from the output.

| `attributes.href` / `src` / `alt` / `width` / `data-*` / `aria-*` | static                                                 | `[A1]` | `"attributes": {"href": "${state.entry.data.url}", "data-x": "pre-${state.entry.data.n}"}`    |

### What a single binding may evaluate to

All expressions below are evaluated at build (`[T3] [T4] [T5] [T6] [T8]`):

- Property reads, optional chaining (`state.entry.data.img?.src`), `??`, `||`, `&&`, ternaries, `!`, comparisons, template literals nested inside (``${`a-${x}`}``).
- Numbers print as digits (`42`, `0`), `false` prints `false`, an object prints `[object Object]`, an array prints its elements joined by commas.
- Array methods and `.length` (`tags.map(t => t.toUpperCase()).join(', ')`), `Math`, `JSON`, `String`, `Date`, `Intl` are in scope; arrow functions and regular expression literals work inside an expression `[H3]`.
- In `textContent` and attributes the value is HTML-escaped by the emitter (`Tom & <Jerry>` prints `Tom &amp; &lt;Jerry&gt;`) `[T7]`.

## 2. Conditional rendering

What the built HTML contains when the condition is false, measured `[Q1]..[Q5]`:

| Construct                                                                                        | Condition false                                                                      | Needs JS |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ | -------- |
| `attributes: {hidden: "${!show}"}`                                                               | element **present**, no `hidden` attribute when `show`; `hidden` attribute when not. | no       |
| flat `style: {display: "${show ? 'flex' : 'none'}"}`                                             | element present, `display:none` in its rule                                          | no       |
| `children: ["${show ? [node] : []}"]`                                                            | element **omitted** from the HTML                                                    | no       |
| `{"$prototype":"Array","items":"${show ? [1] : []}","map":node}`                                 | container empty, rendered by the client                                              | yes      |
| `{"$prototype":"Array","items":{"$ref":"#/state/flag"},"map":node}` with `flag` a template state | static when true; client render when false (empty array)                             | yes      |
| `$switch`                                                                                        | container empty, rendered by the client                                              | yes      |

wp2jx uses the first: `attributes.hidden` with the element's own `style` carrying `"&[hidden]": {"display": "none !important"}`, which `blockVisibility` returns ready to merge (`hidden`, `hiddenStyle`). The rule is needed because Cwicly's `.classID{display:flex}` rules have the same origin as the page and beat the user agent's `[hidden]{display:none}`: without it the element is hidden only when its class sets no `display` `[Q1]`.

A condition that is decidable at conversion time (a static page, a post's own ACF value) is not emitted at all: `blockVisibility` returns `omit: true` and the converter returns no nodes.

## 3. Escaping and literal text

| Text                                                           | In `textContent` / attribute                                   | In `innerHTML`  |
| -------------------------------------------------------------- | -------------------------------------------------------------- | --------------- |
| no binding anywhere in the string: `C:\path `tick` {brace} $5` | verbatim `[E1]`                                                | verbatim `[E1]` |
| a binding in the string: literal `\`                           | write `\\` `[E1]`                                              | write `\\`      |
| a binding in the string: literal `` ` ``                       | write `` \` `` `[E1]`                                          | write `` \` ``  |
| literal `${`                                                   | cannot be written; `&#36;{` prints as the text `&#36;{` `[E2]` | `&#36;{` `[E2]` |
| `$` followed by `{` split across two strings                   | `["a $", "{x}"]` prints `a $\n  {x}`                           | n/a             |

`escapeTemplate` (`src/jx-util.ts`) is the `${` rule for `innerHTML`. `finishBindings` applies the backslash and backtick rule to the literal parts of any string that holds a binding. `$` anywhere else, a lone `{` or `}`, `5 < 6` and `&` need no care.

A literal `${` in a `textContent` or attribute value is degraded to `$\u200b{` (a zero-width space) and reported as `token.literal-template`; the real data has none (checked over both sites).

## 4. Loops

```json
{
  "tagName": "ul",
  "children": {
    "$prototype": "Array",
    "items": { "$ref": "#/state/entry/data/rows" },
    "map": {
      "tagName": "li",
      "attributes": { "data-n": "${$map.item.n}" },
      "textContent": "${$map.item.name} #${$map.index}"
    }
  }
}
```

- `{"$ref":"#/state/entry/data/terms/topic"}` (nested pointers) and `{"$ref":"#/state/all"}` with `all` a `ContentCollection` work, static and JS-free under `timing: "compiler"` `[L1] [L4]`.
- Inside `map`: textContent, attributes, flat style, `innerHTML` and `$props` bindings evaluate per item `[L2]`. `$map.item` of a collection is `{id, data}`: `${$map.item.data.title}`, `${$map.item.id}`.
- Rows are separated by `"\n  "` in the HTML, like all siblings the emitter joins.
- An empty array, or a pointer to a missing field, leaves `<ul data-bind :render="_children0"></ul>`: the whole `children` of the parent is rendered by the client and the static siblings are missing from the HTML `[L3]`. A repeater that can be empty therefore becomes an `innerHTML` expression: `"innerHTML": "${(state.entry.data.terms?.topic ?? []).map(x => '<li><a href=\"' + x.url + '\">' + x.name + '</a></li>').join('')}"` `[H4]` (the values need the inline escape of section 5).
- Components inside a map take `$props` from `$map` `[M4]`.

## 5. Inline escaping for text inside `innerHTML`

`innerHTML` does not escape a binding. A plain-text value written there uses this expression (this is what `finishBindings` writes for a text binding that lands in markup) `[H3]`:

```
${String(EXPR ?? '').replace(/[&<>"']/g, c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]))}
```

An HTML binding (wysiwyg) is written as is: `${state.entry.data.body ?? ''}`.

## 6. Dates

`date` and `modified` frontmatter are strings in UTC (`"2024-02-15T17:30:00Z"`, not `Date` objects) `[D1]`.

```
${new Date(state.entry.data.date).toLocaleDateString('en-US', {year:'numeric', month:'long', day:'numeric', timeZone:'America/New_York'})}
```

prints `February 15, 2024`; `23:30Z` on Dec 31 prints `December 31, 2023` in New York. A time is `new Intl.DateTimeFormat('en-US', {timeZone, hour:'numeric', minute:'2-digit', hour12:true}).format(new Date(x))`. The zone is the site's `timezone_string` (UTC when absent, a fixed offset becomes `Etc/GMT∓N`).

### 6.1 PHP date formats in an expression

`dateExpr(ctx, format, dateExpression)` (`src/cwicly/tokens.ts`) writes PHP's `date($format)` as one expression: `Intl.DateTimeFormat('en-US', {timeZone, ...})` asked only for the parts the format reads, `formatToParts`, then a concatenation. It covers every format character PHP has (`d D j l N S w z W F m M n t L o Y y a A B g G h H i s u v e I O P p T Z c r U`, `x` and `X`), backslash escapes and literal text, and prints a letter that is not a format character as it is, as PHP does. `T` is the zone's tzdata abbreviation as far as the runtime names it (`EST`, `BST`), else the offset (`+04`), the same as the static road's. The tests evaluate it against PHP-faithful `php.date` for 22 formats, 18 instants (a leap day, the ordinal suffixes of the 1st to the 31st, the ISO week of New Year, both daylight-saving changes) and seven zones (names, a fixed offset, UTC, Ireland's negative daylight time), and it agrees on every one. A date picker holds a day, not an instant: the entry stores it as `YYYY-MM-DD`, and it is formatted in UTC so that a zone west of Greenwich does not print the day before; a date-time picker is an instant and is formatted in the site's zone. A missing date prints nothing (`(x) ? expr : ''`), never `Invalid Date`.

`{currentdate}`, `{customcurrentdate}` and the other clock tokens use `Date.now()` as the instant, so they print the date of the last build `[D2]`.

## 7. Components

A component is a document `{"tagName":"fp-card","state":{...},"children":[...]}` registered through `$elements`. Verified `[M1] [M2] [M3] [M4]`:

- `state` defaults are used when the instance passes nothing; `$props` override them, bound or literal.
- Inside the component the rules of section 1 apply to `${state.<prop>}`: text, attributes (`href: "${state.url || false}"`), `hidden` (`attributes.hidden`), flat style, `innerHTML`.
- A bound prop that evaluates to `undefined` becomes `null` (prints `null` inside a template with literal parts); coalesce at the instance.
- Object props arrive as objects (`state.link?.href`); a prop default of an object is replaced by the instance's object as a whole.
- `attributes.hidden` and flat `style` on the instance's tag work like on any element.

## 8. How wp2jx writes bindings

Four modules do it, and they share one resolver. `src/cwicly/tokens.ts` resolves the tokens Cwicly saves in markup; `dynamic.ts` rebuilds what a block's attributes say (text, image, background, gallery) and resolves it through the same table; `links.ts` does the link wrapper and `conditions.ts` the visibility conditions. Because the attribute road and the saved-markup road end in the same code, they cannot disagree, and the tests hold them to it on every block of both sites (section 8.8).

### 8.1 Three modes

`ctx.mode` decides what a value is.

| Mode        | A value that belongs to the post is                                                                                                                         | Used for                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `static`    | the value itself, known at conversion time (`ctx.subject.post`, only when `ctx.subject.kind === "post"`)                                                    | `pages/*.json`                                |
| `entry`     | a binding on `ctx.entryExpr` (`state.entry`, or `$map.item` in a query loop) following the Entry data contract; the current taxonomy term on `ctx.termExpr` | `pages/<base>/[slug].json`, archive templates |
| `component` | not available: a component has no entry of its own, so the token is `token.unresolved`; its own parameters are `${state.<key>}` through `ctx.props`         | `components/*.json`                           |

What is the same in every mode is **site-wide**: the site title and tagline, the site and home addresses (the site root), a fixed page or term (`{pageobject}`), an attachment's file and size, ACF values of a fixed object (an options page, `term_N`, a post by id), and the clock.

| ACF true/false                                              | `1` or empty                                                                                                                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| term of the entry                                           | `E.data.terms.<taxonomy>[i].{slug,name,url}`                                                                                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

An ACF field is found by its **key** (`field_6985035a0b7cb`), which is what a token and every `dynamicACFField` holds. The location argument selects the object: nothing, `false` or `currentpost` is the current post; a number a fixed post; `option` the options page; `term_N` a fixed term; `currenttaxonomytermarchive` the archive's term (`T`); `taxterm` and `termquery` the loop's term; the user forms (`currentuser`, `currentauthor`, `userquery`, `user_N`) need a user and are `dynamic.unsupported`. A field inside a repeater needs the row of its loop (`ctx.rowExpr`, a contract request); a field inside a group is a path.

The **fallback** a token or block carries (`dynamicStaticFallback`, the fifth argument of `{acffield}`, a fallback image id or address) is `|| <fallback>` over the value, in both modes. An image fallback is the attachment id first, then the address next to it: the id of an attachment that was deleted has no file, while the address still names the file the editor showed.

### 8.3 Terms (`ctx.termExpr`)

Taxonomy-archive templates read the current term through `ctx.termExpr` (`state.term`): a content entry of the taxonomy's collection with the contract's naming, `${T.data.name}`, `${T.data.description}`, `${T.data.slug}`, `${T.data.url}` and its ACF term fields `${T.data.<key>}`. A `termExpr` that names a loop item (`$map.item`, inside a `taxonomyterms` or term query loop) is a term reference with no `data`: `${$map.item.name}`, `${$map.item.url}`; it carries no custom fields, and a field read from it is unsupported. `{archivetitle}` is `T.data.name`, or the plural label of the post type in an `archive-<type>` template. Property tokens (`{taxterms=name}`, `{termquery=slug}`) know `name`, `slug`, `description`, `taxonomy` and `url`.

### 8.4 Component props (`ctx.props`)

`{component=parameter=<propId>}`, `{component=content=<propId>}` (the connector the block names) and `{component=link=<propId>}` / `{component=image=<propId>}` become reads of `state.<key>` through `ctx.props`. Prop types decide the shape: `text` is a string, `richtext` is HTML (an HTML binding, raw in markup), `link` is `{href, target?, rel?, title?}`, `image` is `{src, alt?, width?, height?}`. `blockLink` and `blockImage` read the other attributes of a link or image property (`${state.k?.target || false}`), which a string token cannot carry. Parameter variants: `boolean`, `lg`/`md`/`sm` are the value; `accordionopen` is `'cc-accordion-active' : 'cc-accordion-hidden'`; `listIconActive` is `'cc-icon-list' : ''`. A parameter the component does not have is `token.unresolved`.

### 8.5 The seam between a binding and HTML conversion

`htmlToNodes` and `htmlToContent` escape every literal `${` they find, so a binding in the markup they parse would be destroyed. Bindings therefore cross them as opaque private-use placeholders (`bindingMarker`, `src/jx-util.ts`) and become real bindings afterwards (`finishBindings` for strings, `finishNodes` for the nodes and content they return). `tokenContent` and `tokenNodes` in `src/cwicly/tokens.ts` resolve, convert and finish in one call; use them for any markup that may hold a token. `tests/html-bindings.test.ts` proves a placeholder survives text, attributes, inline style values and raw-gap `innerHTML`, and builds the result.

Final-form strings (what `resolveTokens`, `blockText`, `blockLink`, `blockImage`, `blockBackground` and `blockVisibility` return) contain real `${...}` bindings, literal parts escaped for the place they are written, and no placeholders. **Every literal is escaped**, whatever it came from: an address, a title, a label, a relation, a phone number, a fallback, an alt text. A `${` in one is split with a zero-width space and reported once per subject (`token.literal-template`), so a hostile or careless value can never run in the build; `literalFinal` and `finalForm` (`tokens.ts`) are the two ways to write one. The two private-use characters that bracket a placeholder are removed from every literal (`token.private-use`), so a text cannot spell a placeholder of its own. A value spliced into a tag's attribute (`alt="{imagealt=29}"`) has its double quotes escaped too, which Cwicly itself does not do (a stored alt with a quote breaks the tag on the live page); the same quote in a text is left for `wptexturize` to curl. `resolveTokens(text, ctx, block, {where})` takes `where: "attribute"` (default) or `"text"` (a value the Jx emitter escapes) or `"html"` (markup: a text value is escaped by its expression, an HTML value is raw, a literal `${` is `&#36;{`). `{marked: true}` returns placeholders, only to be handed to `finishNodes`.

`finishNodes` also repairs the two places where a naive conversion breaks (rule 5): a bound text child becomes a `<span>` with `textContent`, and a `textContent` that holds an HTML binding becomes `innerHTML`. Inline content that would show a gap beside an element (`<span class="before">#</span>{title}`) is kept raw as `innerHTML` by `htmlToContent`, and the binding inside it escapes itself.

Structure a string cannot carry is a marker element, which the converter that owns it replaces: `{menu}` is `<wp2jx-menu data-menu="<term id>">`, `{nav_menu=ID}` the same, `{postcontent}` is `<wp2jx-post-content>` (exported as `MENU_TAG`, `POST_CONTENT_TAG`). `{menuname}` is the real label (`menuAriaLabel`, else the menu's name). The tests build both: they come out as empty custom elements, never as text.

### 8.7 Text as WordPress prints it

The live pages of both sites print their blocks' static text through `wptexturize`: `Don’t`, `9:00 AM – 5:00 PM`, `…`, curly double quotes, in template parts as much as in posts. So **markup is texturized** (`texturizeHtml`: text only, never a tag, a comment, an attribute, or `pre`/`code`/`kbd`/`style`/`script`/`tt`) whenever it is resolved as markup, and a static `{title}` is texturized as `the_title` does. `texturize` is `wptexturize` of wp-includes/formatting.php written rule for rule, in its order: the static replacements (`...`, ` (tm)`, the cockney words as a plain `str_replace`), the apostrophe and quote patterns with WordPress's `wptexturize_primes` (a prime only after a digit and only where no quotation closes), the dashes and the multiplication sign, with `&nbsp;` counting as a space and a quotation counting the closing quotes already there. It was checked against the real function (PHP 8.3, the live site's own formatting.php) over about 7,000 real fragments of both sites' blocks and 6,000 random strings with no difference, and a committed list of 132 strings and markups with what the real function made of them is a test. A binding's placeholder is masked while it runs, so no rule reaches into one. The oracle is also the live pages: 249 texts on fineline and 28 on anabaptistperspectives agree after it, and the excerpt cards of the blog index agree character for character.

An **entry** prints a bound value as the collection stores it, so for the two modes to print the same text the collections module must write the entry as WordPress prints it. `postData(ctx, post)` is that entry, the reference for the contract: `title` texturized, `excerpt` as text (tags stripped, which is what a static page does before it cuts and texturizes) texturized, ACF text and textarea values texturized, wysiwyg values through `wpautop` and texturized. `postFacts(ctx, post)` is the same post as a static page reads it, with the text as stored; the two differ only in that. The tests compare an entry evaluated over `postData` with the static page with nothing applied on top. This is a contract request.

`{postexcerpt}` is Cwicly's filter, not Rank Math's: the post's own excerpt, else the markup of its text blocks (headings, paragraphs and lists, inside Cwicly's layout blocks, minus the blocks that print the excerpt themselves), then `wp_strip_all_tags` and the byte cut. `excerptOf(post)` is exported so the collections module writes the same `excerpt`. `{postdate=published=5}` is `human_time_diff` as WordPress 5.3 and later prints it: `30 seconds`, `5 minutes`, `2 days`, `1 year`.

### 8.8 What the plugin means, and where this tool differs on purpose

Read from `core/includes` and the editor's `build/index.js`; each is held by a test over the real data.

- **`hideConditions` shows the block when the conditions are true** (`cc_conditions_maker` is the render condition), whatever the editor's label says. `hideConditionsType` is `&&` unless it says `||`; with `||` and no usable entry the block is never shown. An entry with no `condition` or no `operator` is skipped. `hideConditionsToggle` turns the whole list off.
- **Gutenberg stores only what differs from `block.json`.** The token the editor writes uses the default: a `postdate` block with no date attributes is `{postdate=published=default}`; `linkWrapperType` is `url` and `linkWrapperSourceType` is `static` unless stored; `dynamicWordPressAuthorInfo` is `description`; `backgroundImageType` is `static`.
- **A link-wrapped block's saved tag already is the link** (`<a href="{pageurl}">`), so the converters can take the markup; `blockLink` is the same destination from the attributes, ported from the editor's builder. A static object (`linkWrapperStaticObject`) names a post or term and is resolved through `ctx.urlFor`; when it is not on the converted site the stored address beside it is used instead (PHP prints nothing), and it is reported (`link.unresolved`). All 8 such blocks of fineline name the page 482, which is not in the export (the quote page is 1013 now).
- **An image's `src` is its stored address unless a size is chosen** (`imageThumbnailSize`, or a lightbox), in which case it comes from the attachment id; width, height and alt come from the id. An address no attachment accounts for is kept (and reported by the URL rewrite) rather than swapped for the file of an id that may be stale. An image with no id has an empty alt, however much alt text its file's attachment has, because that is what the live page prints. A dynamic image's own alt text wins over the stale id's, and a stated alt (`imageAlt`) over both. Both sites' blocks agree with the saved markup on `src` for all 482 image blocks; the one `alt` that differs is the dynamic-image rule above, which PHP does by injecting an attribute no string substitution can.
- **A dynamic background** is the custom property `--background-image` in the element's inline style, which `cc-main.css` reads (`background-image: var(--background-image)`).
- **Avatars and users.** A static site has visitors, not users: `{username}`, `{userinfo}` and the user's picture are what a guest sees (the block's fallback, else nothing), `{userid}` is `0`, `userrole`/`usercapabilities` conditions and `hideLoggedIn`/`hideGuest` are decided for a guest (`condition.approximated`), and an ACF field read from a user (`currentauthor`, `userquery`) is `dynamic.unsupported` with the block's fallback image. The author's own picture on anabaptistperspectives (the one live difference in 57 images) lives in the author's profile, which the export does not carry.
- **`{postdate=published=5}`** (the relative "5 minutes ago") is frozen at conversion time on a static page (`token.frozen-date`) and printed as the full date in an entry.
- **A value of `0` is empty.** `ACF::processor` starts with `if ($field)`, so a field whose value is `0` or `"0"` prints its fallback, or nothing, and an ACF condition on it (`empty($field)`) says it is empty. Both modes do the same.
- **Rank Math opens the external links of a post's content in a new window** (`new_window_external_links`, applied when it filters `the_content`): `blockLink` gives an external address `target="_blank"` and `noopener` when the context is a post (a page, or a reusable block in one) and the block states no target of its own. A template or a part is not content and is left alone, as on the live pages (the footer's map link has no target there). The saved markup of such a link has no target, so the corpus test compares the two roads with this one difference named.
- **Where the plugin is quirky and this tool follows the evident intent.** `posttag ===` compares the raw `data` with the lower-cased tag names, so `Featured` never matches live; the tool lower-cases `data` and matches. `postcategory !=` compares the term's id with the category names and is always true live; the tool negates the membership. An operator that has no branch for its condition pushes no result in the plugin (it does not count in an `||`); the tool counts a condition it cannot decide as true and reports it (`condition.dropped`). No entry of either site uses these, so the live pages cannot decide, and mirroring the quirks would hide blocks the author meant to show.
- **The author's picture** (a dynamic image from an ACF user field, `currentauthor`) is replaced by the block's fallback image and reported (`dynamic.unsupported`, once per subject). The export has no `usermeta`, so the file the live page shows (the author's own photo on every essay and episode of anabaptistperspectives) is not carried; `wp/model.ts` would have to read it.

### 8.9 Conditions

`blockVisibility` returns, for a block that has any:

- `omit: true` when every visitor gets the same answer and it is "hidden": a static page whose ACF field is empty, `hideGuest`, a post type that is not the entry's. The converter returns no nodes.
- `hidden`, a binding for `attributes.hidden` (`${!(!!(state.entry.data.x))}`), and `hiddenStyle`, the rule that makes the attribute win over the block's own `display` (section 2). The tests build both and evaluate the binding over real entries.
- `deviceHide`, the breakpoint keys at which the block is `display:none`, for `device` conditions the cascade can express (desktop only, not on mobile). Tablets only, or phones and tablets only, would need a hide at the base and a show below it: `condition.approximated`, shown everywhere.
- `dropped`, one line per condition no static site can express (date and time, cookies, request parameters, WooCommerce, comments, shortcodes, a PHP function, a query's count the block was not given). It counts as true, so the block stays, and it is reported (`condition.dropped`). A device condition combined with others by `||` is such a condition: it counts as true, so the block stays on every device.
- A reference to a post or term the converted site has no page for (a podcast, a form entry) is still there: the field is filled, with an empty address (`dynamic.unrouted-reference`, info), so an `acf notempty` condition on it keeps its block. All 88 episodes of anabaptistperspectives that hold a podcast in the fixtures keep their audio player.

What becomes a binding: ACF empty, not empty, true, false and comparisons (`===`, `!=`, `contains`, `notcontain`, `before`, `after`, `<`, `>`, `<=`, `>=`; the ordering operators and `!=` compare two numeric strings as numbers and anything else by characters, as PHP does, so `querycount > 5` is true for ten items; `===` is strict); `postfeaturedimage`, `postexcerpt`, `postcontent`, `posttitle`, `authorname`; `postterm`, `postcategory`, `posttag` (by slug and taxonomy); `has_tags()` and `has_post_thumbnail()`; `queryhasitems`, `querycount` and `queryissinglepage` when the converter passes `{queryCount: "<expression>"}`.

### 8.11 What the other modules need to match (contract requests)

1. `ConvertCtx.urlFor` has no kind for an **author** or a **post type archive**; `tokens.ts` reads `ctx.urlForAuthor(id)` and `ctx.urlForArchive(type)` when present (the routes module's `UrlTools` has both). Without them `{authorurl}` and `{archiveurl}` are `token.unresolved`.
2. The entry data contract needs **`authorUrl`** (the author's page) for `{authorurl}` and author links in entry templates.
3. **Text as WordPress prints it** (section 8.7): the collections module writes what `postData` returns: `title` texturized, `excerpt` (`excerptOf(post)`, tags stripped) texturized, every ACF text and textarea value texturized, wysiwyg values (and textareas with `new_lines: wpautop`) through `wpautop` and texturized, so an entry prints what the live site printed.
4. A repeater's rows need an expression: `ctx.rowExpr` (`$map.item`), read when present, so `{acfrepeater=sub}` and fields inside a repeater can be bound.
5. A query converter that wants `queryhasitems`, `querycount` and `queryissinglepage` as bindings passes `{queryCount}` to `blockVisibility`.
6. The core-block converters should texturize the text of `core/*` blocks too (the live pages do): `texturizeHtml` is exported.
7. The entry holds **`hasExcerpt`** (a boolean: the post has an excerpt of its own), for the `postexcerpt` condition; `excerpt` alone cannot say, because it is generated from the content when the post has none.
8. The entry's **`terms`** are written in WordPress's order, by name: `postData` shows it (`{postcategory}` and `{tag}` are the first of a list, and `{posttags}` prints the list).
9. A converter that converts a post's own content with `blockLink` passes a context whose subject is that post; a template or part is converted with its own, so that Rank Math's external-link rule is applied to the content only.

## 9. Jx behaviour found while measuring (upstream, worked around here)

- Under `timing: "compiler"` a templated `className` or `id` is dropped without a warning `[C1]`.
- A top-level `hidden`, `title`, `tabIndex`, `lang` or `dir` template is emitted statically and also bound on the client `[X1]`.
- A template in a nested style block is dropped without a warning `[S4]`.
- The selector of an element's own style is built from the raw first class or `id`, so a template there yields invalid CSS `[C2]`.
- A template in a string child of `children` is printed literally, and `isDynamic` does not count it, so a page whose only template is a text child ships the literal `${...}` `[K1]`.
- A single-expression template that is nullish is left to the client even when the page is otherwise static `[A4]`.
- Every page that has a `ContentEntry` without `timing: "compiler"` ships `app.js` even when nothing is bound `[TIM2]`.
- Not measured: image optimisation of an `<img>` whose `src` is a binding (sharp cannot load on this machine); a missing source file is tolerated and the `<img>` keeps the evaluated `src`.
